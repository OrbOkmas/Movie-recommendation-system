# TF-IDF Movie Recommendation Pipeline — Usage Guide

This guide documents the TF-IDF baseline and mood-query evaluation used in the **Movie Recommendation System** project. It is intended for teammates running the code in **PyCharm** or from a Terminal.

## Quick start: use the 100-movie sample

From the **repository root** (`Move-recommendation-system/`):

```bash
# 1. Install Python dependencies in the environment you intend to use.
python -m pip install -r requirements.txt
python -m nltk.downloader wordnet omw-1.4

# 2. Train the baseline once on the preprocessed sample.
python -m src.baseline train \
  --data data/processed/sample_clean_movies.csv \
  --output models/tfidf_sample \
  --text-column text_tfidf \
  --query-mode wordnet

# 3. Try a single natural-language mood query.
python -m src.baseline search \
  --index models/tfidf_sample \
  --query "I feel like watching something gloomy and thrilling" \
  --top-k 5
```

Then open **`notebooks/02_mood_query_evaluation.ipynb`** in PyCharm, set:

```python
INDEX_DIR = ROOT / "models" / "tfidf_sample"
```

Select a working Jupyter kernel and use **Run All** to run the saved evaluation queries. **Do not retrain the model for each query.**

## 1. Files and responsibilities

| File / folder | Purpose | When to run or edit |
| --- | --- | --- |
| `data/processed/sample_clean_movies.csv` | Preprocessed 100-movie dataset provided by data engineering; semicolon-separated, with `text_tfidf`, IDs and titles | Input only; do not execute |
| `data/processed/clean_movies.parquet` | Full preprocessed movie dataset, when provided by data engineering | Input only; used for full-data training |
| `src/tfidf_text.py` | Query preprocessing shared by the baseline: removes conversational filler, tokenizes, removes stop words and applies WordNet lemmatization | Imported automatically; normally **do not run directly** |
| `src/baseline.py` | TF-IDF training, saving/loading the index and searching for similar movies | Run `train` when data/model settings change; run `search` to test a query |
| `models/tfidf_sample/` | Saved TF-IDF vectorizer, movie matrix, metadata and training configuration | Generated by training; **do not execute or edit manually** |
| `evaluation/mood_queries.json` | Shared mood-query test set, identified by `query_id` | Edit to add new test queries |
| `notebooks/02_mood_query_evaluation.ipynb` | Runs all test queries, exports rankings, prepares human judgments and computes evaluation metrics | Run after a model exists; rerun after queries or ratings change as described below |
| `evaluation/mood_judgments.csv` | Human relevance grades for retrieved query/movie pairs | Edit the `relevance` column manually (0, 1 or 2) |
| `evaluation/results/tfidf/` | Exported rankings, statuses, metrics and failure candidates | Generated by the notebook; review, compare or archive results |

The pipeline has two parts:

1. **Training (occasionally):** preprocessed movie texts → `baseline.py train` → saved TF-IDF index.
2. **Retrieval and evaluation (repeatedly):** user mood query → `tfidf_text.py` → `baseline.py search` → ranked movies → evaluation notebook → human ratings and metrics.

## 2. `src/tfidf_text.py` — What it does

This helper processes **new queries** in a way consistent with the existing `text_tfidf` movie column. It provides:

- `strip_query_filler(query)`: removes initial framing such as “I feel like watching” or “Can you recommend me”.
- `preprocess_tfidf_text(text)`: uses spaCy English tokenization, alphabetic tokens, lowercasing, spaCy stop-word removal and NLTK WordNet lemmatization.
- `preprocess_tfidf_query(query)`: strips filler and then applies text preprocessing.

For example, `"I feel like watching something gloomy and thrilling"` is reduced to content-bearing terms such as `"gloomy thrilling"`.

**Important:** The movie column is **already** processed. Do not apply this function to the existing `text_tfidf` column a second time. The current stop-word strategy also loses negations such as `not`, so requests like “dark but not scary” are a known limitation to discuss in the failure journal.

You normally do **not** click Run on this file. `src/baseline.py` imports it during search.

## 3. `src/baseline.py` — Train, search and save

### Training

The `train` command reads the movie data, validates required columns (`imdb_id`, `tmdb_title`, selected text column), fits a `TfidfVectorizer` and saves a sparse movie-by-term matrix. The input's `text_tfidf` values have already been cleaned by the upstream data preprocessing pipeline.

The default configuration includes up to **50,000 features**, unigrams and bigrams, a **4,000-word maximum per movie document**, and L2-normalized TF-IDF vectors. Some longer documents may be truncated: record that warning as an evaluation limitation.

Training produces:

```text
models/tfidf_sample/
├── tfidf_vectorizer.joblib   # Fitted vocabulary and vectorizer
├── tfidf_matrix.npz          # Sparse numerical movie vectors
├── movie_metadata.csv        # Movie IDs, titles, etc.
└── manifest.json             # Config and training statistics
```

### Search

The `search` command **loads** those saved files. It normalizes the query via `tfidf_text.py`, transforms it using the saved vocabulary, scores the movies and returns ranked matches (with IDs, titles, similarity scores and available metadata). Since movie and query vectors are normalized, their dot product corresponds to cosine similarity.

Use a different `--query` value to try a new question. Searching does **not** retrain the model.

### Re-training or changing parameters

If you change the dataset, the selected document text, or vectorizer settings, fit a **new index**. Prefer a new output path so that previous results remain reproducible. To deliberately replace an existing index, the script supports `--overwrite`.

Only load `.joblib` files created by your own team; `joblib` loading is not safe for untrusted model files.

## 4. `notebooks/02_mood_query_evaluation.ipynb` — Evaluate recommendations

The notebook **does not fit a TF-IDF model**. It imports `TfidfMovieRecommender` from `src.baseline`, loads the existing index, and processes the queries in `evaluation/mood_queries.json`.

In PyCharm:

1. Open `notebooks/02_mood_query_evaluation.ipynb`.
2. Select a Python kernel with the required packages. The notebook and Terminal can use **different environments**.
3. In the first code cell, set `INDEX_DIR` to the **exact saved model folder** (`tfidf_sample` or `tfidf_full`). The original cell otherwise prefers `tfidf_wordnet` and falls back to `tfidf_sample`.
4. Select **Restart Kernel → Run All**. Examine the query-status table: `ok` means recommendations were returned; `no_matches` means none matched; `error` means processing failed.
5. Inspect the recommendation rankings and exported files.
6. Fill out the human judgment CSV; then rerun the **metrics and subsequent cells** (Section 7 onward) to update evaluation metrics.

The source notebook's query execution and exports are separate from the human-scoring sections. You can rerun individual cells in order as long as their earlier variables still exist in the kernel.

### Query file format

`evaluation/mood_queries.json` must be a JSON array of objects containing at least unique string `query_id` and string `query` fields; optional fields used for reporting include `category` and `test_purpose`.

```json
[
  {
    "query_id": "M29",
    "category": "mood_theme",
    "query": "A mysterious and atmospheric film set in winter",
    "test_purpose": "Atmosphere and setting"
  }
]
```

This is only an example of an **additional** entry; do not replace the original query list with it. If you fundamentally rewrite an existing query, use a **new ID** so old judgments are not incorrectly reused.

### Exported results

The notebook creates or updates:

```text
evaluation/
├── mood_judgment_tfidf.csv
└── results/
    └── tfidf/
        ├── tfidf_mood_results.json
        ├── tfidf_mood_rankings.csv
        ├── tfidf_query_status.csv
        ├── tfidf_failure_candidates.csv
        └── tfidf_labeled_metrics.csv   # Only after enough human judgments
```

**Be aware:** rerunning the export cells overwrites files with these names in `evaluation/results/tfidf/`. Archive important sample results before running on the full dataset.

## 5. Human relevance judgments

Open **`evaluation/mood_judgments.csv`**, not the Python source code. Each row is a **query/movie pair**, even if the same movie appears under different queries. Rate each recommendation using the query and trustworthy movie context—not just the similarity score:

| `relevance` | Meaning |
| --- | --- |
| `0` | Does not match the requested mood/theme |
| `1` | Partially matches |
| `2` | Strongly matches |
| *(blank)* | Not yet judged |

You can also fill in `reviewer` and `notes`. **Save the CSV** before rerunning Section 7 (evaluation metrics) of the notebook.

The judgment-generation cell preserves existing rows/ratings and adds newly retrieved `(query_id, movie_id)` pairs. It **does not automatically remove stale pairs** and matches on IDs, **not the current query wording**. Back up the file when changing the test set significantly.

The notebook calculates **Precision@5**, **MRR@5**, and **nDCG@5 (judged pool)**. A query counts in these aggregate metrics only if **all five** retrieved recommendations have valid grades of 0, 1 or 2. These are retrieval metrics—not classification accuracy—and the notebook's nDCG ideal ordering is based on the five judged retrieved movies, not all relevant movies in the corpus.

## 6. Switching from sample to the full movie dataset

Once the full preprocessed Parquet file is available, **train a separate index** from the repository root:

```bash
python -m src.baseline train \
  --data data/processed/clean_movies.parquet \
  --output models/tfidf_full \
  --text-column text_tfidf \
  --query-mode wordnet
```

Test it with:

```bash
python -m src.baseline search \
  --index models/tfidf_full \
  --query "A mysterious and atmospheric film set in winter" \
  --top-k 5
```

Then change **one line** in the notebook's first code cell:

```python
INDEX_DIR = ROOT / "models" / "tfidf_full"
```

Restart the kernel and run the notebook from the start. Newly retrieved movies need human labels. The notebook's optional plot lookup currently reads only `sample_clean_movies.csv` with `pd.read_csv`; for comprehensive plot snippets on the full dataset, adapt that lookup to use `clean_movies.parquet` with `pd.read_parquet` and the `imdb_id` / `clean_plot` columns, or provide another appropriate metadata lookup. Simply changing `REFERENCE_DATA` to a `.parquet` filename without changing the reader will **not** work.

**Full-data precautions:** Training needs enough RAM to load the relevant text and fit TF-IDF. `baseline.py` has safety limits on per-document length and total characters; do not override `--allow-large` without checking available RAM. If training fails for memory reasons, discuss a smaller representative subset or adjusted settings with the team and document the trade-off.

## 7. What to rerun when something changes?

| Change | Refit TF-IDF? | Rerun notebook? |
| --- | --- | --- |
| Add new queries to `mood_queries.json` | No | Yes, from the start; rate new pairs |
| Change wording of a query substantially | No | Yes; preferably assign a new query ID |
| Add human grades to `mood_judgments.csv` | No | Only Section 7 (metrics) onward; save CSV first |
| Change query preprocessing in `tfidf_text.py` | Generally no | Yes; check that it still matches movie preprocessing |
| Change movie data or TF-IDF training settings | **Yes** | Yes, using the newly saved index |
| Switch to the full dataset | **Yes** | Yes; use `models/tfidf_full` and add new judgments |

## 8. Troubleshooting

- **`No module named 'spacy'`** — Install spaCy in the **same environment as the failing process**. From Terminal: `python -m pip install -r requirements.txt`. Download WordNet: `python -m nltk.downloader wordnet omw-1.4` or run `nltk.download('wordnet')` and `nltk.download('omw-1.4')` in the notebook. Restart the kernel afterward if needed.
- **Notebook import error: `cannot import name 'TfidfMovieRecommender'`** — Verify you have the complete `src/baseline.py` file, save it and restart the notebook kernel. The notebook imports from **`src.baseline`**, not `src.baseline_tfidf`.
- **Model directory missing** — Train before evaluating, and set `INDEX_DIR` to the actual saved index path.
- **`InconsistentVersionWarning` from scikit-learn** — The index was saved with another scikit-learn version. It may still load, but for reliable final evaluation use matching Python/scikit-learn environments or retrain and evaluate consistently.
- **No matching movies** — The query may contain only removed words or terms missing from the trained vocabulary. Inspect `processed_query`, `status` and the movie candidate pool.
- **Metrics missing** — Check `mood_judgments.csv`: all five recommended movies for a query must have valid `0`/`1`/`2` labels before that query enters aggregate metrics.
- **Wrong CSV delimiter** — The sample input uses semicolons (`;`). `baseline.py` defaults to that delimiter; its `--csv-separator` option can be adjusted for different CSVs.

## 9. For the final project comparison

Train TF-IDF and the semantic model against the **same candidate movie collection**, run the **same query set**, and have humans judge the retrieved movies with the **same relevance scale**. Then compare TF-IDF, semantic and hybrid rankings under matched conditions. Log limitations such as the 4,000-word truncation, query-negation handling, missing vocabulary and possible sample-selection effects. Avoid committing restricted full-text subtitles or unnecessarily large generated model files to a public repository.
