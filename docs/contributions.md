## Vojta — Data acquisition, TMDB alignment and dual-track preprocessing

**Role.** I built the end-to-end data engineering and preprocessing pipeline (`src/extract_opus.py`, `src/extract_opus_metadata.py`, `src/alignment.py`, `src/enrich_tmdb_details.py`, `src/preprocessing.py`) that transforms the raw 24 GB OPUS OpenSubtitles archive and TMDB API metadata into the reproducible 51,616-movie corpus (`clean_movies.parquet`) and 100-movie development sample (`sample_clean_movies.csv`) used by all recommendation models.

| Pillar | My work | Where to see it |
|---|---|---|
| **Data collection & Alignment** | Bypassed `opustools` bilingual bottlenecks to stream the monolingual English OPUS OpenSubtitles `v2018` archive (`en.zip`, 446,612 XML files); extracted IMDb IDs and release years from archive directory paths; deduplicated redundant subtitle uploads down to 140,044 unique IMDb IDs; aligned records via TMDB `/find` (filtering out TV series episodes to isolate **51,616** feature films) and enriched them with genres, keywords, runtime, ratings, and poster URLs using checkpointed API calls. | `src/extract_opus.py`, `src/extract_opus_metadata.py`, `src/alignment.py`, `src/enrich_tmdb_details.py` |
| **Dual-track preprocessing** | Built a streaming, memory-safe preprocessing pipeline (`src/preprocessing.py`) with automated edge-case unit tests. Stage 1 strips HTML/XML tags, hearing-impaired brackets, watermarks, and repairs OPUS `<w>` token spacing. From this, the pipeline generates two model-specific columns: **`text_tfidf`** (lowercased, stop-word-filtered, WordNet-lemmatized, capped at 10,000 words) and **`text_embedding`** (case- and punctuation-preserving structured text). Implemented a `< 50`-word subtitle fallback so noisy/incomplete subtitle files fall back to metadata and plot synopses. | `src/preprocessing.py`, `data/processed/clean_movies.parquet`, `data/processed/sample_clean_movies.csv` |
| **Exploratory analysis & Quality audit** | Conducted full-corpus EDA (`notebooks/01_data_exploration.ipynb`) verifying `0` primary-key duplicates (`opus_id`, `imdb_id`, `tmdb_id`), identifying `122` legitimate same-year title collisions, auditing missingness (`0.52%` empty plots, `72.36%` keyword coverage, `0.18%` short subtitles), and documenting corpus temporal (pre-2019) and Anglophone coverage biases. | `notebooks/01_data_exploration.ipynb`, `docs/report.md` ("Data and Methodology") |
| **Process reflection & Failure journal** | Experiment 1: resolved OPUS `<meta>` tag absence, TV-episode API checkpoint bottlenecks, Windows `spaCy` multiprocessing file locks (`OSError [Errno 22]`) and neural pipeline stalls, and PyArrow `ArrowMemoryError` during DataFrame `.explode()` operations. | `docs/failure-journal.md` (Experiment 1) |

**Interfaces to teammates.** Downstream retrieval models (`src/baseline.py`, `src/semantic.py`, `src/semantic_v2/`) and the UI application consume `data/processed/clean_movies.parquet` (or the 100-row `sample_clean_movies.csv` exported with `;` delimiters and `utf-8-sig` encoding) directly via `imdb_id` / `tmdb_id`, reading `text_tfidf` for lexical indexing, `text_embedding` / `clean_plot` / `clean_subtitles` for dense encoders, `has_valid_subtitles` for subtitle filtering, and `poster_url` for frontend display.

## Eliška — TF-IDF baseline, its evaluation, the shared test queries and project setup

**Role.** I built the lexical baseline that every other method is compared against, wrote the 28 mood queries that all models (TF-IDF, semantic v1, semantic v2) are tested on, built the evaluation notebook that scores the baseline with Samuel's relevance labels, and set up the repository structure and the first versions of the project documents.

| Pillar | My work | Where to see it |
|---|---|---|
| **Data & Methodology** | TF-IDF retrieval baseline: sparse movie-by-term index (unigrams + bigrams, 50,000 features, sublinear TF, L2 normalisation) trained once and saved, with ranking by sparse query dot product (cosine similarity) and no all-pairs similarity matrix. Query preprocessing that matches the preprocessed `text_tfidf` column: conversational filler removed, spaCy tokenisation, stop-word removal, WordNet lemmatisation. Input validation and a CLI for `train` / `search`. Documented decisions, including the 4,000-word document limit (7 of 100 movies truncated). | `src/baseline.py`, `src/tfidf_text.py`, `models/tfidf_sample/`, `docs/tfidf_pipeline.md` |
| **Shared test set** | Designed the 28 mood queries M01–M28 used for **all** models, split into 5 categories that each test something specific: direct mood (6), mood + theme (6), subtle vibe (6), negation (6) and edge cases (4: vague, misspelled, empty…). Each query has an ID, a category and a stated test purpose, so results can be compared query by query across methods. | `evaluation/mood_queries.json` |
| **Comparison & Error analysis** | Evaluation notebook that runs all queries, exports rankings, builds the judgment sheet (0 / 1 / 2) and computes Precision@5, MRR@5 and nDCG@5 from the relevance grades. To keep the scale consistent, Samuel labelled the results of every model. The same relevance scale, sheet format and metric code were later reused for the semantic evaluations. The notebook also exports a status for each query (results / no results / rejected) and the failure candidates for error analysis. TF-IDF result, using Samuel's labels: P@5 0.322, MRR@5 0.456, nDCG@5 0.481 on the 23 comparable queries. It works best when the query shares words with the movie text (M16, P@5 = 0.8) and worst on negation (M23, P@5 = 0). | `notebooks/02_mood_query_evaluation.ipynb`, `evaluation/mood_judgment_tfidf.csv` (labels: Samuel), `evaluation/results/tfidf/` |
| **Process reflection & Failure journal** | Experiment 2: no results for vague, misspelled and empty queries (M25, M26, M28), negation lost through stop-word removal, keyword matches that miss the mood, and document truncation. Each with evidence, change and lesson. These failures shaped what semantic v1 and v2 set out to fix. | `docs/failure-journal.md` (Experiment 2), `docs/report.md` ("TF-IDF Baseline") |
| **Project setup & Documentation** | Created the repository folder structure (`src/`, `notebooks/`, `data/processed/`, `models/`, `evaluation/`, `docs/`) and started the shared documents (README, report, failure journal and contributions templates) that the team then filled in. | repository root, `README.md`, `docs/` |

**Interfaces to teammates.** The baseline can be imported (`TfidfMovieRecommender`) or run from the command line, and the trained index is loaded without retraining. `docs/tfidf_pipeline.md` explains how to switch from the 100-movie sample to the full dataset and what to rerun when something changes.

## Matyáš — Semantic Search v2 (improved semantic retrieval) and its evaluation

**Role.** I designed, implemented and evaluated the second semantic retrieval model (`src/semantic_v2/`), whose job is to beat semantic search v1 and the TF-IDF baseline on the same queries and judgments. Every part below is mapped to the grading pillar it serves.

| Pillar | My work | Where to see it |
|---|---|---|
| **Data & Methodology** | Profile of the full corpus (51,616 movies, 2.25 M chunks) and the design decisions derived from it: separate field vectors, explicit handling of missing fields, chunking, hub correction with a background query bank, z-score fusion, query processing (negation, clauses, spelling, statuses). Streaming, sharded and resumable index build for the 2.4 GB corpus. Encoder choice based on measured encoding time. | `docs/semantic_v2_plan.md` (decisions D1–D10 with rejected alternatives), `docs/semantic_v2.md`, `evaluation/results/v2/data_profile.json`, `encoder_timing.csv` |
| **Comparison & Error analysis** | Evaluation protocol: separate dev set of 50 queries written for tuning (33 core, 17 robustness) and the team's M01–M28 as test; corrected nDCG (ideal from the judged pool) next to the team metric, bootstrap intervals, paired differences; label-free diagnostics (hub concentration, typo/paraphrase stability, status accuracy, latency); generated results and error-analysis report on concrete failing queries. Comparison of v2 with TF-IDF and the four v1 variants on identical judgments. | `docs/semantic_v2_results.md`, `scripts/make_results_report.py`, `src/semantic_v2/evaluate.py`, `evaluation/dev_queries.json` |
| **Process reflection & Failure journal** | Experiments 7–13: damaged data copy, false negations, wrong spelling corrections, clause over-splitting, abstention by score failing, encoder chosen by compute, flaw of the shared nDCG. Each with evidence, change and lesson. | `docs/failure-journal.md` |
| **Critical thinking & Defense** | Limitations written down (rule-based negation, real-word typos, residual hubs, untuned weights, small sample, design informed by test queries); conservative defaults (the parser leaves unsure cases alone; the whole query is always scored); 70 automated tests that fix the expected behaviour. | `docs/semantic_v2.md` ("Known limitations"), `tests/` |

**Interfaces to teammates.** The app can call `SemanticSearcher.search()` directly and receives a Python list of results (no CSV needed; see `docs/semantic_v2.md`, "Using it from the app"). I reused the team's queries, relevance scale and judgment sheet format so that results are comparable with Tomáš's v1 evaluation.
